# 画册风格系统 V1（固定版）

适用范围：本仓库后续所有同系列产品子画册（HTML A4 画册）。
基线版本来源：`ectms_brochure.html`（已固化 tag：`v1.0-brochure-scene`）。

## 1. 目标

确保后续画册在以下维度一致：
- 品牌识别一致：颜色、字体、间距节奏、卡片语言统一。
- 版式结构一致：6 页信息架构与视觉重心稳定。
- 交付质量一致：A4 导出不变形，打印可用，线上预览可用。

## 2. 设计锁定项（不可随意改）

以下属于 `V1 锁定资产`，默认禁止修改。若必须改，走“重大版本升级流程”。

### 2.1 颜色 Token（锁定）

来自 `ectms_brochure.html` 顶部 `:root`：
- `--blue: #007bff`
- `--blue-deep: #0f4c81`
- `--ink: #1f2937`
- `--muted: #67758a`
- `--line: #dbe3ee`
- `--surface: #f5f7fa`
- `--surface-blue: #eef5ff`

规则：
- 主强调色只用 `--blue`（或同体系变量），禁止引入新主色。
- 危险/预警信息只用 `--danger` 体系。

### 2.2 字体与排版（锁定）

- 字体栈：`IBM Plex Sans`, `PingFang SC`, `Noto Sans SC`, `Segoe UI`, `sans-serif`
- 主标题、二级标题、正文、说明文字的级差保持当前风格。
- 行高策略：标题紧凑（约 1.15~1.25），正文舒展（约 1.6~1.75）。

### 2.3 画册物理规格（锁定）

- 每页尺寸：`210mm x 297mm`（A4 竖版）
- 禁止因响应式覆盖破坏 A4 固定尺寸预览。
- 打印规则必须保留（`@page`、分页逻辑、页间边距逻辑）。

### 2.4 组件语言（锁定）

- 胶囊眉题（eyebrow）
- 卡片化信息块（含轻阴影、圆角）
- 总结条（insight bar）
- 标签（mini tag）
- 版本矩阵表格样式

规则：
- 可以换内容，不换组件风格。
- 可以调文案长度，不改组件视觉语义。

## 3. 可变项（允许改）

### 3.0 关键原则：结构可变，视觉不变

当子产品的页面逻辑发生变化时，按“双层协议”执行：
- 视觉协议（固定）：颜色 Token、字体体系、卡片语言、表格语言、阴影圆角、A4 规格。
- 结构协议（可变）：每页内容顺序、页数分配、叙事章节、模块组合方式。

换句话说：你可以重排页面逻辑，但必须继续使用同一套视觉组件与 Token。

执行方法：
1. 先在纸面定义新信息架构（例如从 6 页改为 5 页，或把“硬件页”前置）。
2. 再从 `templates/brochure_template_visual_v1.html` 选用组件组装新结构。
3. 禁止为适配新结构而临时发明新风格（新颜色、新阴影体系、新标题体系）。
4. 若确实需要新组件，先在母版补充组件，再用于子画册。

推荐做法：
- 使用“页面蓝图”命名法：`P1-封面`、`P2-痛点`、`P3-方案矩阵`、`P4-能力`...
- 每个页面只描述“信息目标”，视觉实现统一复用模板组件。
- 页面目标变了可以重排，组件语言不能漂移。

### 3.1 可改内容
- 产品名称、定位语、功能描述
- 矩阵条目内容
- 区域办事处与联系方式
- 图像素材（在同风格前提下）

### 3.2 可改范围
- 间距微调：建议不超过当前值的 +/- 15%
- 字号微调：建议不超过当前值的 +/- 10%
- 单页信息密度：保证 A4 不溢出为前提

### 3.3 不建议改
- 品牌蓝主色系
- 页级结构顺序（1~6 页）
- 卡片、表格、摘要条的视觉语言

## 4. 子画册标准流程（建议固化）

1. 从 `ectms_brochure.html` 复制新文件，禁止从空白页重做。
2. 新文件命名：`<product_code>_brochure_v1.0.html`
3. 只替换内容层：标题、正文、矩阵、图片、联系方式。
4. 完成后执行三项检查：
   - A4 预览是否仍是 6 页逻辑
   - 品牌色是否一致
   - 组件样式是否未漂移
5. 导出 PDF 并检查页数、换行、裁切。
6. git 提交并打 tag（见第 6 节）。

## 5. 验收清单（每次发布必过）

### 5.1 视觉一致性
- [ ] `subtitle` 使用品牌蓝体系
- [ ] 组件圆角、边框、阴影风格一致
- [ ] 无突兀新配色（尤其紫色、荧光色）

### 5.2 版式稳定性
- [ ] A4 固定尺寸预览正常
- [ ] 无内容溢出页边界
- [ ] 页间视觉节奏与当前基线一致

### 5.3 业务正确性
- [ ] 联系方式、地址、版本功能点准确
- [ ] 政策条款与编号无误
- [ ] 图文对应关系正确

### 5.4 导出质量
- [ ] PDF 页数正确
- [ ] 无变形、无截断
- [ ] 打印可读性正常

## 6. 版本治理（强烈建议）

### 6.1 分支策略
- 基线分支：`main`
- 子画册开发分支：`brochure/<product_code>-v1`

### 6.2 提交规范
- `feat(brochure): add <product_code> brochure v1.0`
- `fix(brochure): adjust page-6 spacing for A4`
- `chore(brochure): snapshot v1.0`

### 6.3 标签规范
- 主版本：`brochure-<product_code>-v1.0`
- 小版本：`brochure-<product_code>-v1.1`

### 6.4 回滚策略
- 线上或演示异常时，优先回退到最近 tag，不在现场临时改样式。

## 7. 重大改版触发条件（升 V2）

以下任意一项成立，才允许升级风格版本（V2）：
- 品牌视觉策略变更（色彩/字体/调性）
- 页结构从 6 页重构为新叙事框架
- 组件体系有系统性替换

升级要求：
- 先出 `BROCHURE_STYLE_SYSTEM_V2.md`
- 经你确认后再批量迁移子画册

## 8. 落地建议（马上可执行）

- 把 `ectms_brochure.html` 作为“母版”，后续只复制它。
- 把 `templates/brochure_template_visual_v1.html` 作为“结构可变母版”，后续先排信息架构再填内容。
- 新项目先改内容再改图，不先改样式。
- 每个子画册发布时都打 tag，确保可回溯。
