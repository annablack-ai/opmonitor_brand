# 第一部分：更新《智感云官网 V1.0 设计规范｜Codex 交付版》

## 3. 替换整体视觉方向

将原有偏“企业级 SaaS / AIoT 风格”“轻 3D / 2.5D 插画”的描述，统一升级为以下方向。

### 3.1 新视觉关键词

- 白色科技感
- 抽象系统级视觉
- 量子晶格
- 芯片纹理
- 微光网络
- 拓扑流场
- Clinical Blue 医疗蓝
- Pure White 纯白
- Titanium Grey 钛金灰
- Soft Teal 柔和青色
- 高留白
- 克制低饱和
- 精密秩序感
- 企业级可信赖
- 非 SaaS 模板感

### 3.2 新视觉气质

官网整体视觉应体现：

> 专业、克制、抽象、系统化的科技公司官网，而不是普通 SaaS 模板、后台系统、轻 3D 产品说明插画或数据大屏。

视觉应兼顾：

- 面向医院、监管部门、生态环境及危废相关单位的稳重可信；
- 面向科技公司品牌形象的精密、抽象、系统级科技感；
- 面向 AIoT 业务特征的连接网络、感知节点、合规流转和责任闭环。

### 3.3 删除或弱化旧表述

在设计规范中弱化或删除以下表达：

- 企业级 SaaS 风格；
- 轻 3D / 2.5D 作为主视觉方向；
- 大量悬浮 UI 面板；
- 大量管理看板；
- 大量设备示意；
- 通过多个具体产品元素拼贴表达业务能力。

替换为：

- 抽象系统级视觉；
- 白色量子感 / 晶格感；
- 芯片纹理；
- 微光粒子与拓扑网络；
- 开放式流场；
- 高留白、高秩序、高级科技感。

## 4. 更新首页 Hero 设计规则

### 4.1 Hero 新方向

首页 Hero 不再强调具体功能和具体设备，而是表达：

- AIoT 中枢；
- 连接网络；
- 合规流转；
- 秩序感；
- 品牌气场；
- 系统级科技能力。

### 4.2 Hero 禁止项

Hero 主视觉中不应出现：

- 具象垃圾桶；
- 医废桶；
- 危废桶；
- 具体智能称重终端；
- 具体 PDA；
- 具体传感器设备；
- 大二维码卡片；
- 普通云朵图标；
- 大量悬浮仪表盘；
- 大量柱状图、饼图、后台面板；
- 真实人物；
- 医生、护士、患者、监管人员；
- 真实医院、真实客户 Logo、真实后台数据。

### 4.3 Hero 推荐视觉

Hero 推荐使用：

- 抽象 AIoT 核心中枢；
- 白色量子核心；
- 芯片感中枢；
- 量子晶格结构；
- 微光粒子；
- 拓扑流线；
- 合规闭环路径；
- 精密电路纹理；
- 白色 / 极浅蓝空间雾化背景。

### 4.4 Hero 布局规则

- Hero 采用全铺式背景；
- 左侧保留标题、副标题和 CTA 空间；
- 主视觉集中在中部偏右或右侧；
- 不使用包裹整个 Hero 的白色大卡片；
- 背景与下一模块过渡需要柔和；
- 不把 Hero 做成产品说明图。

## 5. 更新首页产品与解决方案模块规则

### 5.1 首页产品模块结构变更

首页“产品与解决方案”模块不再使用 3×2 产品卡片矩阵作为首选结构。

首页产品模块改为：

> 顶部产品切换栏 + 下方单焦点展示区。

结构为：

1. 模块标题；
2. 模块说明；
3. 顶部 6 个产品入口切换栏；
4. 下方当前产品的左文右图展示区。

### 5.2 首页产品切换栏

顶部产品入口包括：

- 医废追溯；
- 危废管理；
- 智慧卫监；
- 消毒灭菌；
- 内镜合规；
- 碳管理。

要求：

- 6 个入口权重平等；
- 默认展示第一个产品不代表主次；
- 当前项有品牌蓝高亮或细底线；
- 入口图标使用抽象几何线性图标；
- 不使用 emoji；
- 不使用黑色裸图标；
- 不使用具象垃圾桶、桶、屏幕、设备图标。

### 5.3 单焦点展示区

左侧内容包括：

- 产品小标签；
- 产品全称；
- 一句话价值主张；
- 3—4 条核心要点；
- CTA 按钮。

右侧内容：

- 先使用高级 CSS 占位；
- 后续由正式 AI 图替换；
- Codex 不生成图；
- 不使用线稿设备占位；
- 不使用灰色图片图标；
- 不出现“图片占位”文字。

### 5.4 3×2 产品矩阵使用范围

3×2 等权产品矩阵仍然保留，但仅用于：

- 产品与解决方案列表页；
- 产品详情页相关推荐；
- 必要时用于移动端降级展示。

首页首屏下方产品展示优先使用 Tab 式单焦点模块，以提升留白、秩序感和官网高级感。

## 6. 更新图标规范

### 6.1 图标总体方向

图标从“功能图标”升级为“产品导航图标系统”。

要求：

- 抽象；
- 几何；
- 系统化；
- 克制；
- 统一线宽；
- 统一尺寸；
- 不具象；
- 不像后台默认图标。

### 6.2 图标尺寸与颜色

顶部产品导航图标：

- 尺寸：28px—32px；
- 线宽：1.8px—2px；
- 默认颜色：蓝灰色；
- 选中态：品牌蓝；
- 可使用极浅蓝背景或底部细线高亮。

### 6.3 禁止图标

不要使用：

- 垃圾桶图标；
- 医废桶图标；
- 危废桶图标；
- 普通警告三角裸图标；
- 普通楼宇图标；
- 温度计直白图标；
- 链条图标；
- 叶子单独图标；
- emoji；
- 黑色裸图标。

### 6.4 推荐图标语义

| 产品 | 推荐语义 |
|---|---|
| 医废追溯 | 标签节点 / 流转路径 / 责任留痕 |
| 危废管理 | 赋码节点 / 合规路径 / 规范化流程 |
| 智慧卫监 | 监管雷达 / 监测网络 / 预警节点 |
| 消毒灭菌 | 参数波形 / 环形监测 / 过程留痕 |
| 内镜合规 | 流程闭环 / 接口连接 / 合规链路 |
| 碳管理 | 流向曲线 / 碳账路径 / 协同分析 |

## 7. 新增 Codex 小步执行规则

在设计规范末尾新增以下规则。

### 7.1 总原则

Codex 不允许一次性执行“整体高级感优化”。

每次只允许修改一个明确模块，并且每次修改必须可独立回滚。

### 7.2 每次执行前必须说明

- 本次修改目标；
- 将修改的文件；
- 不会修改的模块；
- 预期视觉结果；
- 风险点。

### 7.3 每次执行后必须提供

- 修改摘要；
- 修改文件列表；
- PC 截图；
- 移动端截图；
- 是否影响其他模块的说明。

### 7.4 每轮提交建议

```bash
git add .
git commit -m "docs-update-visual-direction"
```

后续页面修改时按模块提交，例如：

```bash
git commit -m "refine-visual-tokens-and-icons"
git commit -m "refactor-home-product-tabs"
```
