# 智感云六大产品线 VI 统一规范｜Icon 与 AI 概念图 Prompt 版

> 用途：统一智感云六大产品线在官网、产品详情页、PPT、宣传物料、图标、概念图、流程图与后续 AI 配图中的视觉识别体系。  
> 核心原则：不通过颜色区隔产品线，而通过统一品牌风格下的“命名编码、图标、视觉母题、业务逻辑配图、素材规范、文案结构”形成系列感与区分度。  
> 适用产品线：HSIMS - 智慧卫监综合管理平台、MWIMS - 医疗废物精细化追溯系统、HWIMS - 危险废物“五即一码”规范化管理系统、DSIMS - 消毒灭菌在线监测系统、ECTMS - 内镜合规平台、PCMS - 减污降碳协同管理系统。

## 1. VI 统一目标

智感云六大产品线不是六个独立品牌，而是同一个 AIoT 软硬一体合规平台能力在不同业务场景中的落地。

六大产品线 VI 不采用“每条产品线一个颜色”的方式区隔，而采用统一品牌系统下的差异化表达：

- 统一蓝白冷感科技风；
- 统一英文编码与中文名称规则；
- 统一线性 icon 风格；
- 统一平面线条业务逻辑配图风格；
- 统一抽象概念图风格；
- 统一网页版式与信息层级；
- 统一素材命名与目录结构；
- 统一文案字段；
- 统一禁止项；
- 统一 Codex 引用规则。

产品线之间的区别主要通过以下方式体现：

1. 产品英文编码；
2. 产品展示名称；
3. 产品短名称；
4. 产品业务语义；
5. 产品 icon 符号；
6. 产品视觉母题；
7. 产品首页介绍右侧业务逻辑配图；
8. 产品详情页真实流程图、软件截图和硬件图内容。

不得通过大面积色彩切换造成“六个不同品牌”的感觉。

### 2.2 官网展示规则

- 产品名称应保留英文编码，推荐格式为：`英文编码 - 中文正式名称`；
- 产品详情页 Hero、产品列表页标题、产品资料封面优先使用“官网展示名称”；
- 首页导航、Tab、Mega Menu、按钮、面包屑等空间较小的位置，可使用短名称；
- 英文全称可作为辅助信息出现在产品详情页 Hero 副信息、产品资料封面、技术参数页、PPT 产品体系页、页脚产品说明或下载资料中；

- 不得出现同一产品多个简称混用的情况。

### 2.3 产品线下级编号使用原则

产品线下的细分产品、模块、终端、子系统、版本或资料包编号，属于公司产品管理体系的一部分，需以公司既定规则为准。

VI 文档不自行定义子产品编号，也不建议临时创造 `MWIMS-01`、`HSIMS-A1` 等示例编号，避免与市场销售、产品报价、交付配置或内部管理口径冲突。

使用原则：

- 子产品编号由公司根据市场销售、产品组合、报价结构、客户交付和内部管理需要统一确定；
- 官网、PPT、产品资料中如需展示子产品编号，应直接使用公司已确认编号；
- 未确认编号不得出现在官网前台、产品资料封面、报价资料或正式宣传物料中；
- 对外展示时，子产品编号应与中文说明同时出现，不能只展示编号；
- 首页和产品总览页以产品线编码为主，不展示过多子产品编号；
- 产品详情页、资料下载页、技术参数页可在合适位置展示已确认的子产品编号；
- 英文编码负责体系感与专业感，中文名称负责客户理解，销售编号负责产品配置和交付管理。

## 3. 产品线 VI 总体视觉原则

### 3.1 不使用颜色区隔产品线

六大产品线统一使用智感云品牌视觉系统。

允许使用：

- 品牌蓝；
- 冰蓝；
- 冷白；
- 浅灰蓝；
- 银灰；
- 极低饱和青蓝。

不允许：

- 每个产品线一个大面积主题色；
- 医废蓝、危废黄、碳管理绿等强色块分区；
- 产品页背景色显著不同；
- 彩色 icon 区隔产品；
- 产品线卡片使用不同强烈渐变。

### 3.2 统一风格关键词

所有产品线视觉统一遵循：

- 蓝白冷感；
- 高端 B2B 科技；
- AIoT；
- 软硬一体；
- 精密系统；
- 秩序感；
- 合规闭环；
- 业务留痕；
- 可追溯；
- 平台化；
- 克制、洁净、专业；
- 不解释过度；
- 不堆信息图。

### 3.3 产品线差异化方式

产品线差异不靠颜色，而靠“视觉母题”。

## 4. 六大产品线 Icon 体系

### 4.1 Icon 总体风格

六大产品线 icon 与官网 icon 体系保持一致：

- monochrome black line icon；
- vector icon；
- outline style；
- geometric minimalism；
- no fill；
- no color；
- no gradient；
- no shadow；
- no 3D；
- no cartoon；
- no emoji；
- no realistic rendering。

### 4.2 Icon 使用位置

产品线 icon 用于：

- 首页产品 Tab；
- 产品列表页卡片；
- 产品详情页 Hero 标签；
- Mega Menu 二级入口；
- PPT 产品体系页；
- 产品资料封面；
- 流程图首节点或分类识别。

### 4.3 Icon 尺寸规范

| 使用场景 | 建议尺寸 |
|---|---|
| 顶部产品 Tab | 28–32px |
| 产品列表卡片 | 32–40px |
| 产品详情 Hero | 36–48px |
| Mega Menu | 22–28px |
| 流程节点 | 20–24px |
| PPT / 物料封面 | 48–72px |

### 4.4 Icon 设计禁用项

禁止出现：

- 垃圾桶；
- 危废桶；
- 医院楼；
- 医生、护士、患者；
- 监管人员；
- 真实硬件设备；
- 真实二维码；
- 真实后台界面；
- 地球、叶子等泛环保符号；
- 夸张警告三角；
- 卡通图标；
- 彩色图标；

## 6. 产品首页介绍右侧配图体系｜平面线条业务逻辑版

### 6.1 配图定位

六大产品首页介绍右侧配图用于产品介绍模块右侧，帮助客户快速理解该产品线“管什么、怎么流转、核心逻辑是什么”。

它不是：

- 品牌氛围图；
- AI 3D 概念图；
- 后台截图；
- 产品结构海报；
- 复杂信息图。

它应该是：

- 平面设计；
- 线条化业务逻辑图；
- 抽象但可理解；
- 能表达业务闭环；
- 与网页整体风格统一；
- 不抢左侧文案，但能增强理解。

### 6.2 统一视觉风格

六张图统一使用：

- Flat Design；
- 细线线条；
- 轮廓化结构；
- 浅底色；
- 蓝灰主色；
- 少量品牌蓝用于强调节点或主路径；
- 局部浅蓝面状色块辅助分层；
- 圆角矩形、圆点、线段、连接路径、流程节点；
- 同一线宽；
- 同一圆角体系；
- 同一信息密度。

明确不使用：

- 极简 2.5D；
- 轻 3D；
- 结构化几何装饰图；
- 真实 UI；
- 真实设备；
- 真实场景；
- 大段文字；
- 人物。

### 12.2 Codex 禁止做

Codex 不得：

- 自行生成 icon；
- 自行使用随机图标库替代已确认 icon；
- 混用不同风格图片；
- 引用 `_drafts` 图片；
- 使用 AI 图冒充真实产品截图；
- 修改 SVG 图标图形内容；
- 添加产品线专属大面积颜色；
- 自行把产品线变成不同主题色页面；
- 用 3D 图替代首页产品介绍右侧平面业务逻辑图。

## 14. 推荐生成流程

### 第一阶段：Icon

1. 先用 Recraft 生成 6 个产品线主 icon；
2. 统一检查线宽、构图、复杂度；
3. 不合格的重新生成；
4. 确认后放入 `public/icons/products`。

### 第二阶段：首页产品介绍右侧配图

1. 先用母版 Prompt 生成 1 张平面线条业务逻辑图作为风格锚点；
2. 确认线宽、节点样式、背景、蓝色强调方式；
3. 再生成六大产品线对应图；
4. 六张图必须同系列；
5. 不合格图进入 `_drafts`，不得进入正式目录。

### 第三阶段：产品详情页概念图

1. 先生成 1 张通用“冷白微晶格 AIoT 概念视觉”作为锚点；
2. 确认风格后再生成 6 条产品线概念图；
3. 六张图必须同系列；
4. 不合格图进入 `_drafts`，不得进入正式目录。

### 第四阶段：网页引用

1. 在 `products.ts` 中配置 icon、overviewImage 和 conceptImage；
2. 在首页产品区 / 产品介绍区使用统一产品 icon 和 overviewImage；
3. 在产品详情页 Hero 使用 conceptImage；
4. 后续再补充真实流程图、软件截图和硬件图。

## 15. 最终判断标准

六大产品线 VI 合格时，应满足：

- 放在一起像同一家公司的一套产品体系；
- 每条产品线又能通过 icon、视觉母题和业务逻辑图区分；
- 不依赖颜色区分；
- 不出现人物、文字、真实设备和敏感场景；
- 首页产品介绍右侧图是平面线条业务逻辑图，不是 3D 图；
- 产品详情页概念图不冒充真实截图；
- 能适配官网、PPT 和产品资料；
- Codex 可通过统一数据结构稳定引用；
- 后续替换图片不会破坏整体风格。

一句话标准：

> 六大产品线应当像同一个 AIoT 合规平台的六个能力方向，而不是六个独立品牌或六套不同风格的页面。
