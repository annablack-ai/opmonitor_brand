# 智感云官网 Carbon 约束清单

适用范围：
- `website_v2_astro/` 官网前台页面
- 首页、产品列表、产品详情、案例、新闻、关于、联系页
- 后续所有视觉优化、前端重构、模块新增与样式调整

目标：
让智感云官网长期维持“医疗科技 + 专业 B2B + 冷静克制 + 可落地可信”的统一气质，避免页面逐步滑向 SaaS 营销页、炫技科技风或拼贴式设计。

唯一外部参考：
- IBM Carbon Design System
- 官方站点：`https://carbondesignsystem.com/`

说明：
这里不是要求官网做成 IBM 官网，而是借用 Carbon 的企业级秩序、留白、信息分层和浅色页面方法，作为长期不会失控的参考母版。

## 1. 总原则

1. 官网必须优先像企业级官网，而不是产品营销落地页。
2. 页面必须先解决信息秩序，再考虑装饰表达。
3. 标题永远是页面或区块中的第一视觉焦点。
4. 背景只能提供气场、秩序和材料感，不能承担“解释内容”的职责。
5. 所有设计判断都必须能解释成规则，不能只说“看起来更高级”。

## 2. 只允许借用 Carbon 的部分

1. 栅格和留白节奏。
2. 标题、正文、辅助信息的层级关系。
3. 模块边界的轻量表达方式。
4. 企业级浅色页面的稳定气质。
5. 信息区块的组织逻辑和可扫描性。

## 3. 禁止直接照搬的部分

1. IBM 产品后台或文档站的工具感。
2. 过密的控件感和后台表单感。
3. IBM 自身品牌语言和文案语气。
4. 过重的系统组件痕迹，导致官网失去品牌感。

## 4. 官网不可违背规则

1. 页面必须以浅色背景为主，不做深色主场景。
2. 页面主强调色只有一个：品牌蓝 `#007BFF`。
3. Hero 不能做产品说明图、流程图、假 UI 面板。
4. 背景不能比标题更吸引注意力。
5. 卡片边界必须轻，不能厚重，也不能靠大阴影制造层次。
6. 模块信息密度可以中高，但必须有清楚层级和留白。
7. 页面不得混入紫色科技风、融资路演风、过度玻璃拟态、廉价 3D、情绪化营销视觉。

## 5. Hero 规则

1. Hero 只承担品牌气场，不承担产品说明职责。
2. Hero 背景可以是抽象光场、微肌理、材料感、秩序感，但不能出现业务标签、功能节点、说明卡片、复杂结构图。
3. 左侧文案区必须保持足够干净，不能被纹理、光晕、几何体或说明元素干扰。
4. 标题、副标题、按钮始终是 Hero 最大的可读焦点。
5. 移动端 Hero 优先保护文案可读性，背景可以继续弱化。

## 6. Section 规则

1. 每个 section 都必须有明确的标题层级。
2. section label、section title、section subtitle 必须统一，不允许每个模块发明一种眉标样式。
3. section 的上下留白必须大于内部卡片间距。
4. 一个 section 只承载一个核心结论，不同时承担多个平级主题。

## 7. 卡片与模块规则

1. 卡片优先用轻边框、轻底色、轻阴影表达边界。
2. 不允许用重阴影、重描边或高饱和渐变制造“高级感”。
3. 数据卡、能力卡、案例卡、新闻卡应遵循统一边界语言。
4. 卡片中的图形和装饰必须服务信息，不允许喧宾夺主。

## 8. 按钮与交互规则

1. 主按钮只允许一种主蓝强调样式。
2. 次按钮只能做轻边框或浅底，不允许再发明第二套主视觉按钮。
3. 动效必须轻、短、克制，只用于反馈和层级，不用于炫技。

## 9. 页面执行顺序

后续优化必须按以下顺序推进：

1. 首页 Hero
2. 首页 section label / section title / section subtitle
3. 首页区块留白与栅格
4. 首页产品模块
5. 首页案例与新闻模块
6. 首页 CTA 与 Footer
7. 产品列表页
8. 产品详情页
9. 案例、新闻、关于、联系页

禁止全站无序同时发散优化。

## 10. 需求表达方式

以后提需求时，不要说：
- “更高级一点”
- “更有设计感一点”
- “更像大厂一点”

改成下面这种判断题：

1. 这一块是否更接近 Carbon 的企业级区块表达？
2. 这个 Hero 是否抢了标题？
3. 这个卡片边界是不是太重？
4. 这个 section 的留白是不是不够？
5. 这个模块是不是更像营销页，而不是企业官网？

## 11. 每轮只改一个问题

正确流程：

1. 只指定一个模块或一个问题。
2. 先说明“不对在哪里”。
3. 按规则做一轮小改。
4. 提供桌面和移动截图。
5. 只做三个决策：保留 / 继续收 / 回退。

禁止一轮里同时改 Hero、配色、卡片、按钮、排版和动效。

## 12. 每轮验收标准

每次改动后只检查这 5 件事：

1. 第一眼是否像企业级官网，而不是 SaaS 营销页。
2. 标题是否仍然是首焦点。
3. 留白是否足够。
4. 模块边界是否轻但清楚。
5. 背景是否只是气场，不是内容。

## 13. 你在整个流程里负责什么

你只负责：

1. 说清楚当前哪一块最不对。
2. 选择更接近哪个固定标准。
3. 在结果出来后决定保留 / 继续收 / 回退。

你不需要负责：

1. 选色值。
2. 选渐变。
3. 选阴影。
4. 选字体层级。
5. 设计 Hero 背景表达。

这些都应该由固定规则来约束，而不是由你临时主观判断。

## 14. 一句话使用方式

以后你只要说：

`这一块按 Carbon 的企业级官网表达收一下。`

这就是最稳的需求表达方式。
