# 智感云官网 V2.0 设计方案｜Astro 组件化交付版

> 版本定位：本方案用于指导智感云官网从快速 Demo 方案升级为正式 V2.0 官网。  
> 技术方向：Astro + Tailwind CSS + TypeScript。  
> 设计目标：图片可控、组件可复用、内容集中维护、后期少折腾。  
> 适用对象：Codex、前端开发、设计协作、后续内容维护。

---

## 1. V2.0 项目定位

智感云官网 V2.0 不再沿用 Tailwind Play CDN 快速 Demo 方案作为正式官网基底。

V2.0 的核心目标不是做一个炫技网站，也不是做一个完全无图网站，而是建设一个：

> 图片可控、组件可复用、内容集中管理、后期少折腾的 B2B 科技公司官网。

官网需要服务以下场景：

- 医疗卫生；
- 生态环境；
- 公共卫生监督；
- 院感合规；
- 危废规范化管理；
- 减污降碳协同。

官网需要传递的品牌感受：

- 专业；
- 可信；
- 清晰；
- 克制；
- 科技；
- 可落地；
- 可长期运维。

## 2. 核心设计原则

### 2.1 不依赖大量 AI 装饰图

V2.0 不是完全不用图片，但不再把高级感押在大量 AI 插画上。

图片策略为：

- 首页 Hero 可以使用 1 张高质量 AI 抽象品牌图；
- 产品详情页必须预留真实业务图片能力；
- 首页产品区不依赖 6 张 AI 图；
- 新闻卡片和案例卡片不强制使用封面图；
- 客户信任主要通过数据、地图、匿名案例和资质建立；
- 后续正式图片由用户提供，Codex 只负责引用和替换。

### 2.2 高级感来自系统，而不是堆素材

V2.0 的高级感主要来自：

- 大留白；
- 强排版；
- 统一组件；
- 统一图标；
- 清晰数据区；
- 克制的色彩；
- 统一间距；
- 轻量 CSS / SVG 抽象背景；
- 产品详情页真实截图与硬件图展示能力。

### 2.3 页面结构必须可维护

所有核心内容不得散落在页面模板中。

产品、数据、新闻、案例、导航、图片路径应集中到数据文件中管理。

后续用户应能够通过“描述需求”让 Codex 修改对应数据或组件，而不是全站到处改 HTML。

## 3. 技术选型

### 3.1 正式技术栈

V2.0 使用：

- Astro；
- Tailwind CSS；
- TypeScript；
- 静态数据文件；
- 本地 SVG icon 或统一开源线性图标；
- 静态图片资源目录；
- CSS / SVG 抽象视觉；
- Vercel / Netlify 等静态部署平台。

### 3.2 不使用的技术

V2.0 第一阶段不使用：

- Tailwind Play CDN；
- React 作为主框架；
- Next.js；
- Nuxt.js；
- Three.js；
- React Three Fiber；
- GSAP；
- Lenis；
- Framer Motion；
- ECharts / Recharts；
- Sanity / Strapi；
- 复杂后端；
- CMS。

### 3.3 不使用 Tailwind Play CDN 的原因

Tailwind Play CDN 适合快速 Demo，但不适合作为正式官网基底。

原因：

- 缺少稳定设计 token；
- 页面越长越容易样式发散；
- 组件复用能力弱；
- Codex 容易局部堆 class；
- 后续维护成本高；
- 不利于统一图片、图标、排版和响应式规范。

## 6. 页面视觉方向

### 6.1 总体风格

- 蓝白科技；
- 白色科技感；
- 高留白；
- 清晰层级；
- 少边框；
- 少阴影；
- 少装饰；
- 图标统一；
- 数据清晰；
- 不做后台大屏风；
- 不做 SaaS 模板插画堆叠；
- 不做多层框框。

### 6.2 色彩系统

建议色彩 token：

```ts
colors: {
  primary: '#007BFF',
  primaryHover: '#006BE0',
  cyan: '#00C2FF',
  heading: '#0B1F3A',
  text: '#334155',
  muted: '#64748B',
  lightMuted: '#94A3B8',
  border: '#E5EEF8',
  bg: '#FFFFFF',
  bgSoft: '#F8FBFF',
  bgBlue: '#F3F8FF',
  bgMist: '#EEF6FF',
  success: '#16A34A',
  warning: '#F59E0B',
  danger: '#EF4444'
}
```

### 6.3 字体层级

PC 端建议：

- Hero 主标题：56px—64px；
- Hero 副标题：18px—20px；
- 模块标题：40px—48px；
- 二级标题：28px—32px；
- 卡片标题：18px—22px；
- 正文：15px—17px；
- 辅助文字：13px—14px。

移动端建议：

- Hero 主标题：34px—42px；
- 模块标题：28px—34px；
- 正文：15px—16px。

### 6.4 间距系统

建议使用统一 spacing：

- 页面 section 上下间距：96px—120px；
- 移动端 section 间距：64px—80px；
- 容器宽度：1200px—1280px；
- 卡片内边距：24px—32px；
- 模块标题与内容间距：32px—48px。

## 7.2 Hero 首屏

### 定位

Hero 是官网品牌气场区，可以使用 1 张高质量 AI 抽象品牌图。

但 Hero 不依赖复杂产品说明图，不堆大量设备、图表、卡片和面板。

### 内容

主标题：

> AIoT 赋能医疗卫生与生态环境智慧合规

副标题：

> 围绕医疗废物、危险废物、卫生监督、消毒灭菌、内镜合规与减污降碳等场景，提供智能终端、业务系统、监管驾驶舱与合规闭环的一体化解决方案。

标签：

- 软硬一体；
- 业务过程留痕；
- 合规闭环。

按钮：

- 预约产品演示；
- 查看解决方案。

### 布局

- 全铺式 Hero；
- 左文右图；
- PC 高度 680px—760px；
- 左侧文案占 42%—46%；
- 右侧视觉占 54%—58%；

### 图片策略

- 不出现“图片占位”文字。

### CSS / SVG 背景方向

- 芯片纹理；
- 拓扑线；

## 7.4 产品与解决方案

### 结构

首页产品区使用：

> 顶部产品切换栏 + 单焦点展示区。

不使用首页 3×2 产品卡片作为主结构。

3×2 产品矩阵保留在产品列表页使用。

### 顶部切换栏

6 个入口：

- 医废追溯；
- 危废管理；
- 智慧卫监；
- 消毒灭菌；
- 内镜合规；
- 碳管理。

要求：

- 权重平等；
- 统一 icon；
- 当前项品牌蓝高亮；
- hover / click 切换；
- 移动端横向滚动或折叠展示。

### 单焦点展示区

左侧：

- 产品标签；
- 产品名称；
- 一句话价值主张；
- 3—4 条要点；
- 了解更多按钮。

右侧：

- 不依赖 6 张 AI 图；
- 第一阶段使用 CSS / SVG 抽象结构图；
- 可表现芯片纹理、拓扑节点、合规闭环、微光网络；
- 后续如果提供正式图，再替换。

### 设计

- 开放式布局，不做大白卡套小卡；
- 减少边框；
- 增加留白；
- 右侧视觉不要像线稿占位；
- 不使用后台截图感的假图。

## 8. 产品详情页模板设计

产品详情页必须支持真实图片展示能力。

### 8.1 页面结构

每个产品详情页使用统一模板：

1. 产品 Hero；
2. 产品定位；
3. 业务痛点；
4. 核心功能；
5. 业务流程图；
6. 软件截图展示；
7. 硬件产品图展示；
8. 场景照片展示；
9. 应用价值；
10. CTA。

### 8.2 产品 Hero

- 左文右图；
- 右侧可使用产品头图或 CSS/SVG 占位；
- 不强制 AI 图；
- 不使用假后台截图。

### 8.3 业务痛点

- 3—5 个痛点；
- 使用文字卡片；
- 每张卡片配轻量 icon；
- 不使用重边框。

### 8.4 核心功能

- 6 个功能卡片；
- 统一 icon；
- 标题 + 简短说明；
- 不堆长段文字。

### 8.5 业务流程图

第一阶段由前端绘制：

- 横向步骤条；
- 节点胶囊；
- 细线连接；
- 移动端纵向展示。

后续可替换为正式设计图，但不依赖图片上线。

### 8.6 软件截图展示

必须预留真实截图能力。

组件：`ScreenshotGallery`

要求：

- 支持 1 张主截图 + 多张缩略图；
- 支持脱敏截图；
- 支持占位图；
- 不允许 AI 假后台图冒充真实截图；
- 截图容器应高级克制，不做多层边框。

### 8.7 硬件产品图展示

组件：`HardwareGallery`

要求：

- 支持白底产品图；
- 支持设备名称；
- 支持适用场景；
- 支持 3—4 个硬件卡片；
- 图片未提供时使用简洁占位，不展示灰色图片 icon。

### 8.8 场景照片展示

用于后续公开授权的现场照片。

要求：

- 仅展示已授权图片；
- 不展示真实敏感信息；
- 不展示患者、业务明细、后台数据；
- 可作为产品详情页后置模块。

### 9.2 图片类型

- 产品截图：`.png`；

### 9.3 Codex 图片职责

Codex 只负责：

- 创建图片目录；
- 配置图片路径；
- 引用正式图片；
- 设置 alt 文案；
- 处理响应式裁切；
- 图片未提供时使用 CSS/SVG 占位。

Codex 不负责：

- 生成图片；
- 找网络图片；
- 引用 `_drafts` 图片；
- 用 AI 图冒充真实产品截图；
- 改变图片风格。

## 14. 动效规范

V2.0 第一阶段只使用轻量动效。

允许：

- hover 上浮；
- tab 淡入淡出；
- 按钮 hover；
- 卡片轻微阴影变化；
- 数字进入视口后轻微出现。

禁止：

- 复杂滚动叙事；
- 大面积粒子动画；
- 页面级 3D；
- 复杂 SVG 动画；
- 页面滚动卡顿的动画；
- 大屏风动态背景。
