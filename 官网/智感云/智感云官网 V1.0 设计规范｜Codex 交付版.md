# 智感云官网 V1.0 设计规范｜Codex 交付版

> 使用说明：本文件用于指导官网 V1.0 的视觉方向、页面结构、组件约束、图片占位策略与 Codex 执行边界。本文档面向 Codex、设计师和前端开发协同使用。

---

# 1. 设计目标

智感云官网 V1.0 的目标是建立一个专业、可信、克制、抽象、系统化的科技公司官网，服务于医疗卫生、公共卫生监督、生态环境、院感合规与减污降碳等高监管业务场景。

官网需要传递以下品牌感知：

- 专业：面向医院、监管部门、生态环境及危废相关单位，视觉表达需要稳重可信。
- 系统化：强调 AIoT 作为连接、感知、流转、留痕和闭环能力的系统级底层支撑。
- 克制：减少模板感、拼贴感和过度功能化表达，强调高留白与秩序感。
- 可信赖：避免夸张炫技、廉价未来感和后台组件库风格，保持长期服务能力的企业气质。

# 2. 整体视觉方向

## 2.1 新视觉关键词

- 白色科技感
- 抽象系统级视觉
- 量子晶格
- 芯片纹理
- 微光网络
- 拓扑流场
- Clinical Blue 医疗蓝
- Pure White 纯白
- Titanium Grey 钛金灰
- Soft Teal 柔和青色
- 高留白
- 克制低饱和
- 精密秩序感
- 企业级可信赖
- 非 SaaS 模板感

## 2.2 视觉气质

官网整体气质应体现：

> 专业、克制、抽象、系统化的科技公司官网，而不是普通 SaaS 模板、后台系统、轻 3D 产品说明插画或数据大屏。

视觉应同时兼顾：

- 面向医院、监管部门、生态环境及危废相关单位的稳重可信。
- 面向科技公司品牌形象的精密、抽象、系统级科技感。
- 面向 AIoT 业务特征的连接网络、感知节点、合规流转和责任闭环。

## 2.3 删除或弱化的旧方向

在后续设计与实现中，应弱化或删除以下旧方向：

- 企业级 SaaS 风格作为主视觉方向。
- 轻 3D / 2.5D 作为首页和主视觉默认方向。
- 大量悬浮 UI 面板、管理看板、柱状图、饼图和大屏表达。
- 通过多个具体设备、终端、二维码卡片拼贴表达能力。
- 首页默认采用 3×2 产品卡片矩阵作为主展示方式。

统一替换为：

- 抽象系统级视觉。
- 白色量子感 / 晶格感。
- 芯片纹理与拓扑网络。
- 微光粒子与开放式流场。
- 高留白、高秩序、高级科技感。

## 2.4 核心设计原则

### 开放式留白优先

页面层次优先通过留白、对齐、节奏、极浅色承托和少量秩序化纹理表达，而不是通过大容器、大边框和厚重阴影表达。

### 抽象系统级表达优先

优先表达中枢、连接、感知、流转、留痕、闭环，而不是具体垃圾桶、具体硬件设备、具体后台界面。

### 首页与列表页分工明确

- 首页：优先使用更高级、更有留白的单焦点展示方式。
- 产品列表页：保留 3×2 等权产品矩阵，承担完整浏览功能。

### 图片与占位职责分离

- 正式 AI 图由外部生成并确认后交付。
- Codex 只负责结构、路径、占位、样式承托和正式引用。

# 3. 首页 Hero 设计规则

## 3.1 Hero 新方向

首页 Hero 不再强调具体功能和具体设备，而是表达：

- AIoT 中枢
- 连接网络
- 合规流转
- 秩序感
- 品牌气场
- 系统级科技能力

## 3.2 Hero 禁止项

Hero 主视觉中不应出现：

- 具象垃圾桶、医废桶、危废桶
- 具体智能称重终端、PDA、传感器设备
- 大二维码卡片、普通云朵图标
- 大量悬浮仪表盘、柱状图、饼图、后台面板
- 真实人物、医生、护士、患者、监管人员
- 真实医院、真实客户 Logo、真实后台数据

## 3.3 Hero 推荐视觉

Hero 推荐使用：

- 抽象 AIoT 核心中枢
- 白色量子核心 / 芯片感中枢
- 量子晶格结构
- 微光粒子
- 拓扑流线
- 合规闭环路径
- 精密电路纹理
- 白色 / 极浅蓝空间雾化背景

## 3.4 Hero 布局规则

- Hero 采用全铺式背景。
- 左侧保留标题、副标题和 CTA 空间。
- 主视觉集中在中部偏右或右侧。
- 不使用包裹整个 Hero 的白色大卡片。
- 背景与下一模块过渡需要柔和。
- 不把 Hero 做成产品说明图。

# 4. 首页产品与解决方案模块规则

## 4.1 首页产品模块结构

首页“产品与解决方案”模块不再使用 3×2 产品卡片矩阵作为首选结构。

首页产品模块改为：

> 顶部产品切换栏 + 下方单焦点展示区。

结构为：

1. 模块标题
2. 模块说明
3. 顶部 6 个产品入口切换栏
4. 下方当前产品的左文右图展示区

## 4.2 首页产品切换栏

顶部产品入口包括：

- 医废追溯
- 危废管理
- 智慧卫监
- 消毒灭菌
- 内镜合规
- 碳管理

要求：

- 6 个入口权重平等。
- 默认展示第一个产品不代表主次。
- 当前项有品牌蓝高亮或细底线。
- 入口图标使用抽象几何线性图标。
- 不使用 emoji。
- 不使用黑色裸图标。
- 不使用具象垃圾桶、桶、屏幕、设备图标。

## 4.3 单焦点展示区

左侧内容包括：

- 产品小标签
- 产品全称
- 一句话价值主张
- 3—4 条核心要点
- CTA 按钮

右侧内容：

- 先使用高级 CSS 占位
- 后续由正式 AI 图替换
- Codex 不生成图
- 不使用线稿设备占位
- 不使用灰色图片图标
- 不出现“图片占位”文字

## 4.4 首页产品模块视觉原则

- 模块采用开放式 section 布局，不依赖大白色外框。
- 顶部切换栏更像产品导航，不像功能按钮栏。
- 下方展示区以留白、对齐、轻承托和右侧主视觉气场组织内容。
- 不使用厚重阴影和复杂边框。
- 不把首页产品区做成后台组件库风格。

## 4.5 3×2 产品矩阵使用范围

3×2 等权产品矩阵仍然保留，但仅用于：

- 产品与解决方案列表页
- 产品详情页相关推荐
- 必要时用于移动端降级展示

首页首屏下方产品展示优先使用 Tab 式单焦点模块，以提升留白、秩序感和官网高级感。

# 5. 图标系统规则

## 5.1 图标总体方向

图标从“功能图标”升级为“产品导航图标系统”。

要求：

- 抽象
- 几何
- 系统化
- 克制
- 统一线宽
- 统一尺寸
- 不具象
- 不像后台默认图标

## 5.2 图标尺寸与颜色

顶部产品导航图标：

- 尺寸：28px—32px
- 线宽：1.8px—2px
- 默认颜色：蓝灰色
- 选中态：品牌蓝
- 可使用极浅蓝背景或底部细线高亮

## 5.3 禁止图标

不要使用：

- 垃圾桶图标
- 医废桶图标
- 危废桶图标
- 普通警告三角裸图标
- 普通楼宇图标
- 温度计直白图标
- 链条图标
- 叶子单独图标
- emoji
- 黑色裸图标

## 5.4 推荐图标语义

| 产品 | 推荐语义 |
|---|---|
| 医废追溯 | 标签节点 / 流转路径 / 责任留痕 |
| 危废管理 | 赋码节点 / 合规路径 / 规范化流程 |
| 智慧卫监 | 监管雷达 / 监测网络 / 预警节点 |
| 消毒灭菌 | 参数波形 / 环形监测 / 过程留痕 |
| 内镜合规 | 流程闭环 / 接口连接 / 合规链路 |
| 碳管理 | 流向曲线 / 碳账路径 / 协同分析 |

# 6. 页面结构建议

## 6.1 首页

页面结构建议：

1. Hero
2. 数据背书 / OPM 大数据
3. 产品与解决方案（Tab 式单焦点模块）
4. 软硬一体能力
5. 客户覆盖与案例
6. 新闻动态
7. CTA

## 6.2 产品列表页

页面结构：

1. 页面 Hero
2. 产品矩阵（3×2 等权卡片）
3. 软硬一体能力简述
4. 预约演示 CTA

产品列表页中的产品卡片可比首页信息更完整，但仍保持六个产品权重平等。

## 6.3 产品详情页

页面结构：

1. 产品 Hero
2. 产品定位
3. 业务痛点
4. 核心功能
5. 业务流程图
6. 软件截图展示
7. 硬件产品图展示
8. 应用价值
9. 预约演示 CTA

要求：

- 截图必须脱敏。
- 可使用占位图。
- 不得使用 AI 生成的假后台图冒充真实系统截图。
- 硬件图优先使用白底产品图或浅蓝产品展示卡。

## 6.4 客户案例页

页面结构：

1. 页面 Hero
2. 客户覆盖数据
3. 中国区域覆盖地图
4. 客户类型卡片
5. 匿名案例卡片
6. 合规说明
7. CTA

## 6.5 新闻动态页

页面结构：

1. 页面 Hero
2. 分类筛选
3. 新闻卡片列表
4. 分页或加载更多

## 6.6 关于我们页

页面结构：

1. 页面 Hero
2. 公司简介
3. 能力标签
4. 资质荣誉
5. 服务网络
6. CTA

## 6.7 联系我们页

页面结构：

1. 页面 Hero
2. 联系信息
3. 预约表单
4. 地图或地址信息

# 7. 组件与视觉表达规范

## 7.1 按钮

主按钮用于预约产品演示、提交需求、查看方案；次按钮用于辅助跳转。

要求：

- 主按钮使用品牌蓝。
- 次按钮使用白底蓝边。
- 不使用厚重发光和高饱和霓虹效果。

## 7.2 卡片

卡片只在确有必要时使用，不应成为首页所有模块的默认容器。

要求：

- 白底、圆角、轻阴影、极浅边界即可。
- 避免多层嵌套框。
- 避免大面积渐变和过强装饰块。

## 7.3 数据区

首页数据区应优先采用大数字矩阵式表达，而不是强卡片式 6 宫格。

## 7.4 图片占位

当正式 AI 图未交付时：

- 允许使用高级 CSS 占位。
- 占位应体现白色科技、芯片纹理、微光节点、拓扑流线。
- 不出现“图片占位”文字。
- 不使用灰色默认图片图标。

# 8. Codex 小步执行规则

## 8.1 总原则

Codex 不允许一次性执行“整体高级感优化”。

每次只允许修改一个明确模块，并且每次修改必须可独立回滚。

## 8.2 每次执行前必须说明

- 本次修改目标
- 将修改的文件
- 不会修改的模块
- 预期视觉结果
- 风险点

## 8.3 每次执行后必须提供

- 修改摘要
- 修改文件列表
- PC 截图
- 移动端截图
- 是否影响其他模块的说明

## 8.4 每轮提交建议

```bash
git add .
git commit -m "docs-update-visual-direction"
```

后续页面修改时按模块提交，例如：

```bash
git commit -m "refine-visual-tokens-and-icons"
git commit -m "refactor-home-product-tabs"
git commit -m "prepare-image-assets-structure"
git commit -m "replace-official-ai-visuals"
```

# 9. Codex 执行边界

Codex 在执行官网页面修改时：

允许：

- 基于已确认文案和信息架构进行结构实现
- 为未到位图片使用高级 CSS 占位
- 处理正式图片路径、alt、响应式裁切和前端引用

禁止：

- 自行生成 AI 图片
- 下载网络图片
- 使用未确认草稿图
- 改变已确认的信息架构
- 增加未经确认的业务内容
- 回退到旧的轻 3D / SaaS 插画方向
